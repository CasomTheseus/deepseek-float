### 第一批的返工（已修）

1. **气泡在真实窗口里完全不显示。** 根因：`KeyframeAnimator(initialValue:trigger:)` 只在 trigger **发生变化**时播放关键帧，而我传的是 `delta.id`——每枚气泡都是全新视图标识，trigger 一生不变，动画永不开始，视图停在 `initialValue` 的 `opacity 0` 上。改成用一个 `onAppear` 才翻转的布尔量驱动。
   **为什么上一轮没发现**：验收用的离屏渲染里有 `snapshotMode` 分支，它绕开了 `KeyframeAnimator` 直接画静态中段帧——所以只验证了"气泡长什么样"，从没验证过"动画会不会跑"。
2. **收起态根本没有气泡。** 气泡只挂在 `BalanceCard` 里，而收起态不渲染该卡片。收起恰恰是桌宠最常驻的形态，必须能看到。
3. **多枚气泡会叠成一团。** 候选清单里写了「多个纵向错开 18pt 排队」，实现里却只是一个 ZStack；两枚同时出现时完全重叠、字都糊在一起。已改为按序号 `offset(y: index * -17)`。这个 bug 是靠 `--render --low` 的验收截图发现的——又一次说明「写了但没看」等于没写。
4. **「窗口永远置顶」开关效果相反**（用户报告）。根因：`@Published` 是在 **willSet** 阶段发布事件的，而我的 sink 写成 `sink { _ in self?.applyLevel() }`，`applyLevel()` 回头去读 `model.alwaysOnTop` —— 那一刻属性还是旧值，于是每次都设成相反的层级。改成 `sink { enabled in self?.applyLevel(enabled) }` 直接用发出来的值。
   **为什么静态测试没抓到**：初始化时 `applyLevel(model.alwaysOnTop)` 读到的已经是加载好的值，所以启动状态是正确的；只有**运行中切换**才会暴露。这也是我第一轮"测量通过"却仍被用户发现问题的原因。
   同时修掉第二个缺陷：`level = .normal` 只改层级、不重排窗口，而 accessory app 的非激活面板不会在别的 App 激活时自动落到后面。实测 `level=0` 时它仍压在**整屏 Safari（1680×1020，完全覆盖本窗口）**之上 ⇒ 关掉置顶等于没效果。现在关闭时主动 `orderBack(nil)`。
   验证方式：`kill -WINCH` 动态切换 + `Tools/ZOrderProbe.swift` 量真实 z 序（见 README）。

配套补上了 `LiveCapture` + `--probe`（`kill -USR1`）：渲染本进程视图层级抓取动画中间帧，不需要「屏幕录制」授权。动画类改动今后必须用它验收，不能再只靠静态渲染。

## 0. 先给结论：什么是可能的，什么是不可能的

我用**实测编译**（不是猜）确认了本机的能力边界：

| 能力 | 结论 | 依据 |
|---|---|---|
| `contentTransition(.numericText())` 数字滚动 | ✅ 可用 | `swiftc -target arm64-apple-macos14.0` 编译通过 |
| `PhaseAnimator` / `KeyframeAnimator` 多段关键帧动画 | ✅ 可用 | 同上 |
| `.visualEffect { }` 几何驱动的实时效果 | ✅ 可用 | 同上 |
| `.symbolEffect(.bounce, value:)` 图标动效 | ✅ 可用 | 同上 |
| `.scrollTransition` 滚动过渡 | ✅ 可用 | 同上 |
| `MeshGradient` 网格渐变 | ✅ 可用 | `-target arm64-apple-macos15.0` 编译通过 |
| Swift Charts 图表框架 | ✅ 存在 | SDK 内含 `Charts.framework` |
| **Liquid Glass 液态玻璃** | ❌ **不可用** | CommandLineTools SDK 是 **15.5**，全 SDK 搜不到 `glassEffect` / `NSGlassEffectView`；且未装 Xcode。要它必须先装 Xcode 26 |

**一个前置代价**：用上面这些动效 API 需要把部署目标从 `macos13.0` 提到 `macos14.0`。你系统是 26.3，提这个等于零成本。

## A. 余额的即时反馈（你点名的那一类）

**A1 · 浮动增减量气泡** ⭐你已点名
余额刷新后若发现下降 Δ，从余额右上角飘出一枚红色 `-¥0.05`，向上飘 ~26pt 同时从 1.0 淡出到 0，历时 1.1s；上涨则绿色 `+¥100.00`。同一时刻多个 delta 纵向错开 18pt 排队。
→ 出处：Revolut / Robinhood 等金融 App 的通用模式（你提出）
→ 成本：低（一个 overlay + KeyframeAnimator）
→ 已实测 API 支撑：`KeyframeAnimator`

**A2 · 余额数字滚动**
数字变化时旧值向上推出、新值从下方滚入，而不是硬切。
→ 出处：iOS/macOS 原生 `.numericText()`；Syrtis、DeepSeek Stats 均用
→ 成本：极低（一行修饰符）

**A3 · 变化瞬间色闪**
数字在下降后的 320ms 内短暂染红、上涨染绿，再 ease-out 回落到正常白。与 A2 叠加。
→ 出处：金融行情类通用
→ 成本：极低

**A4 · 余额"燃烧"进度条**
余额卡底部加一条极细进度条，表示「今日消耗 ÷ 期初余额」，消耗端带橙色发光，像余烬往前烧。
→ 出处：codexU 的「羊毛进度」条（见参考图）
→ 成本：低

**A5 · 心跳脉冲**
正在请求时，状态点向外扩散一圈会消失的光环；请求结束停止。我目前只有静态点。
→ 出处：TokenClock 活跃指示、Syrtis 顶栏 `3.4M tok/min` 的呼吸绿点
→ 成本：极低

**A6 · 消耗速率迷你弧**
余额右侧加一段 40pt 的半圆弧，弧长对应「本小时消耗 vs 历史峰值小时」，让你一眼看出当前是不是在猛跑。
→ 出处：概念自定，形态参考 Syrtis 的额度环
→ 成本：低

## B. 缓存命中的可视化（我们的主角指标）

**B1 · 命中率环弹性回弹**
数值变化时环用 spring 过冲约 4% 再回落，而不是线性补间。
→ 出处：Syrtis / TokenClock 的环形图进场
→ 成本：低

**B2 · 构成条流光**
命中/未命中/输出三段构成条上，一条窄高光每 3s 从左扫到右，暗示数据在流动。
→ 出处：Liquid Glass 组件库（cupertino_native / Glance）常见手法
→ 成本：低（`visualEffect` 驱动）

**B3 · 命中率里程碑光晕**
命中率 ≥90% 时圆环转为青绿并加外发光，同时图标做一次 `symbolEffect(.bounce)`；跌破 60% 转橙。把「省钱」变成一个可被奖励的状态。
→ 出处：codexU 的双环配色分级、DeepSeek Stats 的领先徽章
→ 成本：低

**B4 · 双环对比**
外环 = 缓存命中率，内环 = 输出占总量比例。一屏看两个比例，信息密度翻倍而不加高度。
→ 出处：**codexU 的 `5h 65% / 7d 66%` 双同心环**（见参考图）
→ 成本：低

**B5 · 命中省下的钱**
把「因为命中而少花的钱」直接算出来显示：`命中 165.9万 ≈ 省 ¥1.49`。比百分比更有说服力。
→ 出处：概念自定（我们独有的口径优势）
→ 成本：极低（纯计算，但需要内置命中/未命中单价表）

## C. 图表与趋势

## D. 材质与容器

**D1 · 噪点纹理叠加**
在渐变背景上叠一层极细噪点（64×64 平铺），消除大面积渐变的塑料感。这是让界面"贵"起来最便宜的一招。
→ 出处：Liquid Glass 系组件的标配
→ 成本：极低（Canvas 生成，零资源）

**D2 · 顶部内高光描边**
卡片上边缘加 0.5pt 白色渐隐高光，模拟玻璃被光打到的边。
→ 出处：**DeepSeek Stats 的卡片**、TokenClock 的玻璃边缘
→ 成本：极低

**D3 · 渐变描边环**
卡片边框从纯色改为角度渐变（左上亮、右下暗），随位置变化。
→ 出处：TokenClock 玻璃边缘
→ 成本：低

**D4 · 卡片悬停上浮**
鼠标悬停卡片时上移 1pt、阴影扩散、底色提亮 4%。
→ 出处：Syrtis 的额度卡、codexU 的指标瓦片
→ 成本：极低

**D5 · 背景极光缓动**
我们已有的径向品牌蓝辉光，让它以 22s 周期缓慢漂移+呼吸，窗子"活"起来。
→ 出处：codexU 的紫渐变底、Syrtis 的青绿渐变
→ 成本：极低

**D6 · 主题切换**
浅色 / 深色 / 跟随系统 三态切换。我们目前只有深色。
→ 出处：**codexU 顶栏的 ☀/🌙 三态开关**
→ 成本：中（要重构配色为语义色）

## E. 排版与数字

**E1 · 等宽数字防抖**
余额与所有指标用 `monospacedDigit`，刷新时位数变化不再让布局左右抖动。
→ 出处：全部专业项目
→ 成本：极低（**建议无条件做，这是正确性问题**）

**E2 · 数字/单位层级**
大号数字 + 小一号货币符号 + 大写字距的小标签，三层对比。
→ 出处：Syrtis 的 `$19599.17 / 总计 / 11/16 → 09/26`
→ 成本：低（我已部分做到，可再拉开层级）

**E3 · 小数位弱化**
小数点后两位用小一号、低对比度，视觉重心落在整数位。
→ 出处：金融 App 通用
→ 成本：极低

**E4 · 键盘快捷键提示**
底栏显示 `⌘R 刷新`，并把快捷键真正接上。
→ 出处：**codexU 右下角 `刷新 02:27 ⌘U`**
→ 成本：低

## F. 状态与反馈

**F1 · 骨架屏微光扫过**
首次加载时灰色占位块上有斜向高光周期性扫过，代替现在的转圈。
→ 出处：通用
→ 成本：低

**F2 · 低余额呼吸红晕**
余额低于阈值时，窗口四边内侧出现缓慢呼吸（3s 周期）的红色内发光。
→ 出处：Syrtis 的「将会用完」红条
→ 成本：低

**F3 · 同步成功对勾**
保存/同步成功后，按钮原位弹出一个对勾并淡出，取代现在右上角的纯文字提示。
→ 出处：通用
→ 成本：极低

**F4 · 错误态边框渐红**
接口失败时卡片描边在 400ms 内转为红色再缓慢褪回，不打断阅读。
→ 出处：通用
→ 成本：极低

**F5 · 收起/展开改弹性过渡**
高度变化从 `easeInOut` 换成 spring（response 0.34 / damping 0.78）。
→ 出处：macOS 原生观感
→ 成本：极低

## 我的推荐组合

如果让我挑一套**性价比最高、且不会把窗口搞得花里胡哨**的：

| 组别 | 编号 | 理由 |
|---|---|---|
| **必做（正确性）** | **E1** | 等宽数字是防抖动的正确做法，不是装饰 |
| **灵魂一条** | **A1 + A2 + A3** | 你点名的浮动红字，配数字滚动和色闪，三者是一套完整反馈 |
| **主角指标** | **B4 + B3** | 双环 + 里程碑光晕，把「缓存命中」做成这个窗口的视觉签名 |
| **你已拍板** | **C1** + 上一轮的第 1 项（峰时/闲时、每百万 token 均费） | 功能增量 |
| **质感打底** | **D1 + D2 + D5** | 噪点 + 边缘高光 + 极光缓动，三条加起来不到一小时，但整体档次的提升最明显 |
| **点睛** | **A5 + F3** | 心跳脉冲 + 成功对勾，让"活着"和"成功了"都有反馈 |

合计 12 条。剩下的（C6 十字线、D6 主题切换、B5 省下的钱）留作第二批。
